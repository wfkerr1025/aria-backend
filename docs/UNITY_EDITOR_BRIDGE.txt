UNITY EDITOR BRIDGE
===================

ARIA (Python) drives an open Unity Editor by writing a JSON file that an
editor script reads, executes and answers. Nothing is manual once the
script is installed: the editor watches for the file on its own.

    Assets/ARIA/Editor/ARIAEditorBridge.cs   the Unity side (editor-only)
    aria/unity_editor_bridge.py              the Python side
    backend/tests/test_unity_editor_bridge.py  tests for the Python side

This is the open-editor sibling of backend/core/unity_ops.py, which starts
a fresh batch-mode editor per call. Use this one when Unity is open.


1. INSTALLING THE UNITY SIDE
----------------------------

Copy the C# file into the Unity project so it lands at

    <UnityProject>/Assets/ARIA/Editor/ARIAEditorBridge.cs

either by hand, or from Python:

    python -m aria.unity_editor_bridge --project "D:/Path/To/UnityProject" --install

Unity compiles it on its next refresh (click into the editor window). The
console then shows:

    [ARIA] Editor bridge 1.0.0 loaded. Commands: <UnityProject>/ARIA/unity_commands.json

It lives in an Editor folder, so it is never part of a build. While the
game is playing it runs only Ping, Screenshot, GetField, GetHierarchy and
SetPlayMode; a batch holding anything that edits a scene waits until the
game stops, because play mode throws such edits away when it ends.

Works on Unity 2021 and later. It uses nothing from URP/HDRP or the
Input System; verified on 6000.3. Screenshot under URP or HDRP needs 2023.1
or later, where cameras take render requests; before that it falls back to
Camera.Render, which only the built-in pipeline supports.


2. TRIGGERING THE BRIDGE IN UNITY
---------------------------------

Three ways, all doing the same thing:

  ARIA > Watch For Commands   (menu, checked = on; on by default)
      The editor looks for the commands file twice a second and runs it
      as soon as it appears. This is what makes Python calls return on
      their own. Turn it off if you would rather trigger runs by hand.

  ARIA > Run Bridge Commands  (menu)
      Runs the commands file once, now. Use it with the watcher off, or
      when a Python call was made with wait=False.

  Batch mode, for a project no editor has open:
      Unity.exe -batchmode -nographics -quit -projectPath <UnityProject>
                -executeMethod ARIA.Bridge.ARIAEditorBridge.RunPendingCommands
      UnityEditorBridge.send_headless() does this for you. Unity refuses
      to start while another editor holds the project, so this is the
      fallback, not the default.

  ARIA > Open Bridge Folder   shows the two files in Explorer.

Every run logs a summary line to the Unity console prefixed [ARIA].


3. WHERE THE FILES LIVE
-----------------------

    <UnityProject>/ARIA/unity_commands.json   written by Python, consumed by Unity
    <UnityProject>/ARIA/unity_results.json    written by Unity, read by Python

<UnityProject> is the folder that contains Assets/. The ARIA folder sits
beside Assets, not inside it, so Unity never imports either file.

Python writes the commands file whole and renames it into place; Unity
does the same with the results file, so neither side ever reads half a
document. Unity deletes the commands file as it picks it up. Each
exchange carries an "id" that the results echo back, so a stale results
file cannot be mistaken for a fresh one.

Which project: pass project_root to UnityEditorBridge, or set the
ARIA_UNITY_PROJECT environment variable; otherwise the Unity plugin's
configured project (backend.core.unity_ops.project_path) is used.
ARIA_UNITY_BRIDGE_TIMEOUT sets how long Python waits (default 60 s).


4. COMMAND SCHEMA
-----------------

A single command:

    { "command": "CreateGameObject", "args": { "name": "Floor", "primitive": "Plane" } }

A batch (what Python always writes):

    {
      "id": "3f1c...",
      "stopOnError": true,
      "commands": [
        { "command": "CreateGameObject", "args": { "name": "Crate", "primitive": "Cube",
                                                   "position": [0, 1, 0] } },
        { "command": "AddComponent",     "args": { "target": "Crate", "componentType": "Rigidbody" } },
        { "command": "SetField",         "args": { "target": "Crate", "componentType": "Rigidbody",
                                                   "field": "mass", "value": 5 } }
      ]
    }

With stopOnError on (the default) the commands after a failure are
reported as skipped rather than run against a scene in an unknown state.

The results file:

    {
      "id": "3f1c...",  "ok": true,  "message": "Ran 3 command(s): 3 succeeded, 0 failed.",
      "bridgeVersion": "1.0.0", "unityVersion": "6000.3.6f1", "project": "...", "finishedAt": "...",
      "results": [
        { "command": "CreateGameObject", "success": true, "message": "Created Crate.",
          "data": { "name": "Crate", "path": "Crate", "instanceId": -1234,
                    "globalId": "GlobalObjectId_V1-2-...", "scene": "Main", "active": true } },
        ...
      ]
    }

Every command answers with success, message and data. A command that
throws inside Unity is reported as a failure with the exception message,
never as silence.

OBJECT REFERENCES  (the "target" argument, also accepted as "gameObject")

    "Root/Child"                            hierarchy path, any loaded scene
    "Assets/Scenes/Main.unity::Root/Child"  hierarchy path in one scene
    "Player"                                a bare name, searched everywhere (inactive too)
    "id:12345"                              instance id (valid for one editor session)
    "gid:GlobalObjectId_V1-2-..."           global id (stable across sessions once the
                                            scene is saved; all zeros before that)

Vectors are [x, y, z] (also {"x":..,"y":..,"z":..} or "x, y, z"). Rotations
are euler degrees [x, y, z], or a quaternion [x, y, z, w]. Colours are
[r, g, b] / [r, g, b, a] in 0..1 (0..255 if any part exceeds 1), a hex
string "#ff8800", or a name "red".

COMMANDS

  Ping               -> bridge and Unity version, active scene
  CreateGameObject   name, parent?, position?, rotation?, scale?, primitive?
                     (Cube/Sphere/Capsule/Cylinder/Plane/Quad), components? [names]
  DeleteGameObject   target
  AddComponent       target, componentType (e.g. "Rigidbody", "UnityEngine.Light",
                     or a script class name), allowDuplicate?
  RemoveComponent    target, componentType
  SetTransform       target, position?, rotation?, scale? (vector or one number),
                     local? (default false: world space)
  SetField           target, componentType? ("GameObject" or omitted = the object itself),
                     field, value
                     Finds the serialized property first ("mass", "m_Mass" and
                     "Mass" all match), then a public property or field. Values
                     may be numbers, bools, strings, vectors, colours, enum names,
                     layer names, or object references (an asset path such as
                     "Assets/Materials/Red.mat", or a scene reference as above).
                     Nested paths work: "m_Constraints", "size.x". "active" on a
                     GameObject calls SetActive.
  GetField           target, componentType?, field  -> data.value
  GetHierarchy       target?, depth?  -> data.objects: [{name, path, instanceId,
                     active, depth, components}], data.scenes
  OpenScene          path (Assets/...unity), additive?, discardChanges?
                     (in an interactive editor an unsaved scene prompts first)
  SaveScene          path? (save-as; folders are created), saveAll?
  CreatePrefab       target, prefabPath (Assets/...prefab), connect? (default true:
                     the scene object becomes an instance of the new prefab)
  ModifyPrefab       prefabPath, operations: [ {command, args}, ... ], stopOnError?
                     Operations run on the prefab's contents; targets are
                     relative to its root ("" or "/" is the root). Allowed:
                     CreateGameObject, DeleteGameObject, AddComponent,
                     RemoveComponent, SetTransform, SetField, GetField,
                     GetHierarchy, CreateLight, CreateCamera. If any operation
                     fails the prefab is left untouched.
  InstantiatePrefab  prefabPath, name?, parent?, position?, rotation?
  CreateLight        type (Directional/Point/Spot), name?, position?, rotation?,
                     intensity?, color?, range?, spotAngle?, shadows? (None/Hard/Soft)
  CreateCamera       name?, position?, rotation?, fov?, clearFlags?
                     (Skybox/SolidColor/Depth/Nothing), backgroundColor?, main?
                     (tags it MainCamera), near?, far?, orthographic?,
                     orthographicSize?. Adds an AudioListener if the scene has none.
  RefreshAssets      path?, force?, recursive?
                     With no path, AssetDatabase.Refresh. With one, that asset
                     is imported and the result DESCRIBES it: guid, the main
                     asset's type, the importer, every Sprite hanging off it,
                     and for a texture its textureType, spriteMode, pixels per
                     unit and readability. Written for the case where a tool
                     put a .png and a hand-rolled .meta on disk and nothing
                     had yet asked Unity what the pair became.
  Screenshot         path?, width? (1280), height? (720), view? (game/scene)
                     Renders through a RenderTexture, not ScreenCapture, so it
                     returns a file that exists rather than one that will. A
                     Screen Space - Overlay canvas draws to the display and
                     appears in no camera's render, so the game view borrows
                     every overlay canvas onto the capture camera for the one
                     frame and hands them back afterwards. Defaults under
                     ARIA/shots/: a screenshot is evidence, not an asset.
  SetPlayMode        playing? (true), testSave? (true), seed? (keep/fresh/real),
                     keepRunning? (true), allowUnfocused?, skipSnapshot?
                     Returns BEFORE it happens. Entering play mode reloads the
                     C# domain and destroys everything holding the call, so the
                     result is written first; send whatever comes next as its
                     own batch. A playing bridge runs only Ping, Screenshot,
                     GetField, GetHierarchy and SetPlayMode (to stop).
                     Entering is refused while Unity is not the focused
                     application (allowUnfocused:true overrides), and the
                     game's persistentDataPath is first copied to
                     ARIA/snapshots, newest ten kept (skipSnapshot:true
                     overrides). Play mode runs the game's own save code
                     against real files; a blank game once replaced a
                     real save that way. Ping reports focused too.

                     THE TEST SAVE. Unless testSave:false, the game plays
                     against ARIA/testsave instead of its real save. The
                     bridge sets the environment variable ARIA_TEST_SAVE_DIR
                     to that folder before play and clears it when play ends;
                     a game that reads it (in the editor only) keeps every
                     file there. seed decides what the folder holds as play
                     begins: keep (as the last test left it; the default),
                     fresh (emptied: a new game), or real (a copy of the
                     player's save, to start where they are with no way to
                     write back).

                     Only SetPlayMode from moments earlier makes a session
                     the bridge's. A person pressing Play always gets the
                     real save: the variable is cleared as any other session
                     begins, and whenever a session ends.

                     A game that does NOT read the variable still writes its
                     real save, so the bridge checks: every file under
                     persistentDataPath is listed as play begins and compared
                     as it ends, and ARIA/last_play.json records
                     realSaveSafe and realSaveTouched (anything created,
                     changed or deleted). A difference is also logged as an
                     error. Unity's own persistentDataPath/Unity caches are
                     not counted. PlayerPrefs live in the registry, not in
                     that folder, and are NOT redirected. Ping reports
                     driving, testSave and lastPlay.

                     KEEP RUNNING. With Run In Background off, an unfocused
                     editor plays no frames: measured on 6000.3, minimized
                     mid-play, the frame count stood still for three seconds;
                     with it on, it climbed 1600 frames. While a test session
                     plays the bridge sets Application.runInBackground, which
                     in the editor is Player Settings' Run In Background too
                     (both read true meanwhile), and hands the old value back
                     as play ends. ProjectSettings.asset is not written unless
                     the project is saved mid-session, and the next save puts
                     that right. keepRunning:false refuses. With testSave and
                     keepRunning both on, an unfocused start needs no
                     allowUnfocused: the focus-lost save lands in the test
                     folder, and the frames come.

                     Entering and leaving play mode bring the editor window
                     to the front. That is Unity's own behaviour, not the
                     bridge's.

                     In a game, the whole of honouring it is choosing the
                     folder (Ore and Odds: SaveSystem.Folder):

                         string test = Application.isEditor
                             ? Environment.GetEnvironmentVariable("ARIA_TEST_SAVE_DIR") : null;
                         string folder = string.IsNullOrEmpty(test)
                             ? Application.persistentDataPath : test;
                     Refused in batch mode. This is what makes Screenshot worth
                     having on a project that builds its interface at runtime:
                     in edit mode there is no interface to photograph, only the
                     scripts that will make one.

  SendInput          actions: [ {...}, ... ]  (or one action's fields directly),
                     allowRealSave?
                     Plays keys, clicks, scrolls and text into the running
                     game, queued and spread over the next frames (a press and
                     its release must land in different frames for
                     wasPressedThisFrame to see them). Ping's inputPending
                     reaches 0 when they have played. Actions:
                       {"key": "space"}               tap; hold? frames (2), times?,
                                                      action? tap/down/up
                       {"key": ["LeftCtrl", "s"]}     held together
                       {"click": [640, 360]}          button? left/right/middle,
                                                      hold?, times?, space? viewport
                       {"click": "Canvas/BuyButton"}  where that object is drawn
                       {"move": [x, y] | path}
                       {"mouse": "down"|"up", "at"?}  button?
                       {"scroll": -120} or [x, y]     up is positive
                       {"text": "hello"}              Keyboard.onTextInput
                       {"wait": 30} / {"waitSeconds": 0.5}
                     Places are pixels from the bottom left of the game's
                     picture (ReadScreen's coordinates), 0..1 with
                     space:"viewport", or an object's path, found as the
                     command arrives. Key names are the Input System's
                     (Space, Enter, Escape, A, Digit1, LeftShift, UpArrow,
                     F5, Backquote) or a character ("`", "1", ",").
                     Sent through two devices of the bridge's own, "ARIA
                     Keyboard" and "ARIA Mouse", which become Keyboard.current
                     and Mouse.current as they send; the real devices are
                     untouched, and the bridge removes its own as play ends.
                     For the length of a test session the Input System is
                     told to send all input to the game whatever has focus
                     (backgroundBehavior IgnoreFocus, editorInputBehavior
                     AllDeviceInputAlwaysGoesToGameView) -- on a copy of its
                     settings, handed back as play ends. Without that, a
                     keyboard or pointer event with the Game view unfocused
                     is kept for the editor and the game never sees it. It
                     also means a person typing in the editor during a test
                     is typing into the game.
                     Refused unless the session is a test (see SetPlayMode):
                     input changes the game, and the game saves what changes.
                     Needs the Input System package; the old Input Manager
                     reads the hardware and cannot be fed. IMGUI text fields
                     (OnGUI) do not hear "text".
  ReadScreen         targets?, includeHidden?, limit? (200)
                     What is on the game's screen, as data: lines (visible
                     text in reading order), texts and controls (each with
                     path, kind, rect and center in pixels from the bottom
                     left, which is what SendInput clicks; controls say
                     interactable, their label and isOn/value/text).
                     Visible means active, enabled, not faded out by a
                     CanvasGroup, not transparent, and on the screen;
                     includeHidden lists the rest. targets: object paths,
                     answered with where each is drawn (a UI element's
                     centre, a world object's renderer centre through the
                     main camera) and whether that is on screen. UI Text and
                     TextMeshPro are found by type name, so the bridge needs
                     neither package. IMGUI (OnGUI) cannot be read back:
                     Screenshot it.

  GetLog             since?, session?, types?, contains?, limit? (100), stack? (true)
                     What the console has said, oldest first: the game's
                     log, warning, error, exception and assert messages, and
                     compiler errors (compileError) with a summary line per
                     compile (compile). data.next is what to pass as since
                     next time, so each read is only what is new;
                     session:true starts from the last bridge-started play
                     session. types "errors" is every kind of fault. Errors
                     carry the first twelve lines of their stack. The newest
                     500 messages are kept and the newest 300 survive a
                     domain reload; asking from before that says so.
                     The bridge's own "[ARIA]" progress lines are left out.
                     Compile errors matter most: a script that does not
                     compile leaves the editor running the scripts that last
                     compiled, this bridge among them, which then answers as
                     if nothing were wrong. Ping reports logNext and
                     sessionErrors; ARIA/last_play.json reports errors and
                     the first five for the session it describes.
                     (ReadScreen, unlike SendInput, reads a session on the
                     real save as well: it only looks.)

Asset paths must start with Assets/ and contain no "..": the bridge does
not write outside the project. A screenshot path is relative to the project
rather than to Assets/, for the same reason it defaults outside it.


5. USING IT FROM PYTHON
-----------------------

    from aria import unity_editor_bridge as unity

    unity.configure("D:/Unity/Projects/Aria Test Project")   # or ARIA_UNITY_PROJECT

    unity.ping()
    floor = unity.create_game_object("Floor", primitive="Plane", position=(0, 0, 0), scale=5)
    crate = unity.create_game_object("Crate", primitive="Cube", position=(0, 1, 0))
    unity.add_component("Crate", "Rigidbody")
    unity.set_field("Crate", "Rigidbody", "mass", 5)
    unity.get_field("Crate", "Rigidbody", "mass")          # -> 5.0
    unity.set_transform("Crate", rotation=(0, 45, 0))
    unity.create_light("Directional", "Sun", rotation=(50, -30, 0), intensity=1.2, color="#fff4e0")
    unity.create_camera("Main Camera", position=(0, 5, -10), rotation=(20, 0, 0), fov=60, main=True)
    unity.create_prefab("Crate", "Assets/Prefabs/Crate.prefab")
    unity.save_scene("Assets/Scenes/Demo.unity")

Each function returns the command's data dict (create_game_object gives
path, instanceId and globalId) and raises UnityBridgeError with the
editor's message when a command is refused. UnityBridgeTimeout means
nothing answered: no editor open, bridge not installed, or the watcher
off.

Several commands in one editor pass:

    bridge = unity.UnityEditorBridge("D:/Unity/Projects/Aria Test Project")
    with bridge.batch() as b:
        b.create_game_object("Enemy", primitive="Capsule", position=(3, 1, 0))
        b.add_component("Enemy", "Rigidbody")
        b.add_component("Enemy", "CapsuleCollider")
    b.results[0].data["globalId"]

Editing a prefab in place:

    ops = unity.Batch()
    ops.add_component("", "Rigidbody")                 # "" is the prefab root
    ops.set_field("", "Rigidbody", "useGravity", False)
    ops.create_game_object("Muzzle", position=(0, 0, 1))
    unity.modify_prefab("Assets/Prefabs/Gun.prefab", ops)

Manual trigger (no waiting): construct with wait=False, call as usual,
then choose ARIA > Run Bridge Commands in Unity and call
bridge.read_results() afterwards.

Plain descriptions, for ARIA's own routing:

    unity.run_unity_command("create a floor plane at y=0")
    unity.run_unity_command("create a cube named Crate at 0,1,0 then add a rigidbody to it")
    unity.run_unity_command("set mass of Crate Rigidbody to 5")
    unity.run_unity_command("create a directional light named Sun intensity 1.5")
    unity.run_unity_command("create a main camera at 0,5,-10 fov 70")
    unity.run_unity_command("make a prefab from Crate")      # Assets/Prefabs/Crate.prefab
    unity.run_unity_command("save scene as Demo")            # Assets/Scenes/Demo.unity

parse_unity_command(text) returns the commands without sending them. A
description the router does not recognise raises UnroutableCommand; it
never guesses. Anything beyond its shapes goes through the functions
above.

From a shell:

    python -m aria.unity_editor_bridge --project "D:/Unity/Projects/Aria Test Project" "create a cube named Crate at 0,1,0"
    python -m aria.unity_editor_bridge --json "what's in the scene"
    python -m aria.unity_editor_bridge --headless "ping"      # starts a batch-mode editor


6. EXTENDING
------------

A new command is one case in RunOne() in ARIAEditorBridge.cs, a method
beside the others returning Ok(...) or Fail(...), its name added to
COMMANDS in unity_editor_bridge.py, and a builder on _CommandBuilder so
both the bridge and Batch get it. The test
test_the_shipped_bridge_dispatches_every_command_the_client_knows fails
if the two lists drift apart.

The transport is one method pair (RunPendingCommands / WriteResults on
the C# side, write_commands / read_results on the Python side).
Replacing the files with localhost HTTP later means replacing those, and
nothing else.
